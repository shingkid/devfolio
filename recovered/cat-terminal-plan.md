# Complete redesign: terminal-native portfolio (full rebuild, off Gatsby)

## Context

The current site is an unmodified fork of the open-source "devfolio" Gatsby template: plain Tailwind grays, a two-column label/content section pattern, hover-scale avatar — the generic developer-portfolio grid the (now-discarded) PRODUCT.md warned against. That PRODUCT.md described a "tea-reading" interaction concept that was never actually built (confirmed via grep — no tea/leaf/cup code anywhere); the user has called it an abandoned prototype and wants a full restart.

New direction, given directly by the user: **a real terminal interface** — futuristic but minimal and clean — referencing doublepiao.com (git-commit-log metaphor, terminal window chrome, GitHub-dark palette, JetBrains Mono + Inter) and kalebnim.dev (CLI/filesystem metaphor, `root@host ~ %` prompt, directory-listing nav with `▸` chevrons, voice-interface CTA). Commands/navigation now; a chatbot representing the user is planned for later and should have room to slot in, but isn't built now.

The user explicitly released the constraint of staying on Gatsby: **the existing repo is content only** (the `siteMetadata` in `gatsby-config.js`, resume PDF, profile photo). Free to use xterm.js or whatever's best suited, and to migrate off Gatsby entirely. The only hard constraints going forward: **easy to edit content, easy (and free) to deploy.** Blog is dropped from scope — it currently has zero posts (just `.gitkeep`), so there's nothing to migrate and no reason to build it now.

## Stack decision

- **Next.js (App Router, TypeScript)**, replacing Gatsby entirely — removes `gatsby-config.js`, `gatsby-node.js`, `gatsby-browser.js`, the `src/pages` Gatsby routing, and all `gatsby-*` dependencies.
- **Deploy on Netlify**, same site/account already hosting this project (README shows an existing Netlify badge/site `jane-seah`) — free tier, and Netlify has first-class Next.js support, so this avoids a DNS/account change if a custom domain is already pointed there. *Operational note: the Netlify site's build settings (framework preset, build command) live in Netlify's dashboard, not this repo — will need a one-time update there after the migration, separate from this plan's file changes.*
- **Tailwind CSS**, carried forward (familiar, still the right tool), reconfigured around new OKLCH design tokens instead of default gray scale.
- **xterm.js** (`@xterm/xterm` + `@xterm/addon-fit`) as the terminal *rendering* engine — gives a real cursor, text selection, resize handling, and a built-in accessibility/screen-reader helper, instead of hand-rolling those. A thin custom "shell" layer on top (command registry → output writer) supplies the actual commands, since xterm.js itself has no shell logic.
- **Content**: a single typed content module (e.g. `content/profile.ts`) mirroring the current `siteMetadata` shape (about, projects, research, experience, education, skills, hobbies, links, resume) — kept as one plain, well-typed file so it's trivial to edit without touching component code.

## Design direction

**Identity, not a copy** of either reference site.

- **Type**: single monospace family throughout (prompt, headings, body, chrome) — proposing **IBM Plex Mono** via `next/font` (distinct from both references' JetBrains Mono, self-hostable, reads as "engineered" — fits an AI Engineer identity).
- **Color**: original OKLCH dark palette (will run the palette script as this is effectively a new brand). Near-black background (low chroma, not pure `#000`), one considered accent carrying prompt text / cursor / links — proposing a cyan-leaning teal (reads as terminal-phosphor without the green-CRT cliché) — plus a muted low-chroma gray for secondary/comment-style text. Accent carries meaning (links, active state, cursor), not decoration.
- **Motion**: blinking cursor, typed/revealed output, `prefers-reduced-motion` fallback (instant render, static cursor). No scanlines/CRT-flicker, no bounce/elastic easing.
- **Prompt identity**: `jane@seah:~$` (placeholder, will confirm visually during build).

## Interaction model

- Persistent prompt + input, command history (↑/↓ recall), tab-completion on command names.
- **Command model, revised: a real filesystem metaphor, not a flat command list.** Each section is a markdown file in a virtual directory (`~/about.md`, `~/projects/`, `~/projects/pawkit.md`, etc.), navigated with `ls`, `cd <dir>`, `cat <file>` / `less <file>` (both print the same styled output — real pager semantics like scrollback/`q` aren't worth building for content this short, so they're aliases, not distinct behaviors), plus `help` and `clear`. This is a stronger fit for "terminal-native" than the flat command list — it's the same directory metaphor kalebnim.dev already inspired (`▸` chevrons, item counts), just carried all the way through — and markdown-as-content-files is arguably a *better* answer to the "easy to edit content" constraint than a single typed TS object: editing a `.md` file needs no code literacy at all.
- **Recruiter discoverability is kept, not traded away, for the fs authenticity.** The existing semantic commands (`about`, `projects`, `experience`, `education`, `research`, `skills`, `hobbies`, `resume`, `contact`) stay as first-class top-level shortcuts — typing (or tapping a chip for) `projects` does the equivalent of `cd projects && ls` (or `cat`, if it's a single file) in one step. Raw `ls`/`cd`/`cat` is there for anyone who wants to explore like a real shell; nobody is required to know it.
- **`cat`/`less` output is styled like [Glow](https://github.com/charmbracelet/glow)** (charmbracelet's terminal markdown renderer): bold accent-colored headings, a colored bullet marker on list items, inline bold/italic, a left-bordered blockquote in muted tone, a horizontal rule, underlined accent-colored links. Prototype gets a small hand-written renderer covering exactly this set (headings/bold/italic/lists/links/hr/blockquote) — not a real CommonMark parser or dependency, since it's one static file with no build step.
- Prompt reflects the current directory once `cd` exists (`janeseah:~$` → `janeseah:~/projects$`), so navigation state is visible, not just implied.
- **Discoverability for recruiters** (the primary audience per the product brief, most of whom won't intuit terminal commands): a visible, always-present row of clickable command chips next to the input — not just a buried `help` command. Also critical on mobile, where typing every navigation action is a poor experience.
- **SEO / no-JS fallback**: xterm.js renders to canvas — it has no textual DOM a crawler or no-JS visitor can read. Next.js SSR must still emit real semantic HTML (headings, lists, real `<a>` links to resume/contact) as the server-rendered baseline; the terminal is progressive enhancement on top of that, not a JS-only wall. `next/head` (or App Router `metadata`) carries the OG/Twitter meta the current `Seo` component provides today.
- Accessibility: keyboard-operable throughout, xterm.js's screen-reader mode wired up, WCAG AA contrast verified directly on the accent-on-dark-bg pairing (dark-mode accents are an easy place to fail 4.5:1), reduced-motion alternative for cursor/typing animation.
- 404 gets an authentic terminal treatment (e.g. `bash: cd: /page: No such file or directory`) instead of a generic error page.
- One clearly-marked extension point (component boundary + a short note in the eventual DESIGN.md) for a future `ask`/chatbot command — not implemented now.

   **Status: still iterating.** The prototype (same Artifact URL, file at `/private/tmp/.../scratchpad/prototype.html`, generated from `prototype-template.html` + inlined Commit Mono woff2s via a small Node substitution script — the build/publish loop already established) has grown a pixel-art cat mascot perched on the terminal's corner: a resident seal-point cat (front-facing, chibi proportions, wide British-Shorthair face, four legs, tail) plus a visiting friend cat (ginger in dark mode, tuxedo in light mode) that currently walks in, hangs out, and walks back out.
